# Hoard repo audit, 7 October 2026

The whole repo was reviewed in five passes:

1. `hoard/` core, part 1: downloader, jobs, egress, browser, library, itch, updates, libraries.
2. `hoard/` core, part 2: server, safety, vault, updater, config, setup, local, projects, tags, diagnostics, app, cli, net, paths, changelog.
3. The app's web pages (`hoard/web/`) and the website (`site/`).
4. The Unity package (`Packages/soloflighter.hoard/`).
5. `scripts/`, `.github/` workflows and `packaging/`.

Each finding came from reading the code, not from running it, unless it says **verified**. Each was confirmed in
the code before it was fixed. "PR #119" marks code that was new in that pull request.

**Status: every finding below is fixed in Hoard 3.0.0 and Hoard for Unity 0.5.2** (pull request #119), each with a
test where it can be tested. `CHANGELOG.md` (3.0.0) and `Packages/soloflighter.hoard/CHANGELOG.md` (0.5.2) say
what changed for people using Hoard; `docs/ARCHITECTURE.md` describes where the shared code now lives.

## 1. Privacy and security (fix first)

| # | Where | Problem |
|---|---|---|
| S1 | `hoard/server.py:590`, `:634` | **A product marked both hidden and removed leaks while the hidden library is locked.** "Removed" is checked first, so `/api/library` and `/api/assets` return its name, picture and files. |
| S2 | `hoard/server.py:658` | **`/api/setup` returns the raw job state.** It skips `public_job`, so a job's traceback (with file paths) and hidden product names reach the page. |
| S3 | `hoard/library.py:344` | **`fetch_jinxxy` follows `/my/inventory?page=N` links on any host.** It opens them in the signed-in Jinxxy browser. The downloader checks `jinxxy_link()` first; the library reader doesn't. |
| S4 | `Packages/…/Core/Credits.cs:112` | **Catalog URLs aren't checked for `)` or spaces in the credits list.** An unsealed catalog can add an extra Markdown link to the credits people paste publicly. |
| S5 | `hoard/server.py:518` | **`_unlocked()` changes the shared `srv.unlocks` dict without a lock.** On threaded requests that can raise "dictionary changed size" or `KeyError`, dropping the request. |

## 2. Data loss or wrong files

| # | Where | Problem |
|---|---|---|
| D1 | `hoard/downloader.py:1268` | **Jinxxy deletes byte-identical thumbnails across products on every sync.** That includes real shared pictures, which the new picture-hash stacking relies on. They're re-downloaded, then deleted again next sync. |
| D2 | `hoard/egress.py:202` | **A resumed download has no ETag, Last-Modified or If-Range check.** A creator's new upload under the same name can be joined onto an old `.part` file. Only itch.io checks a checksum. |
| D3 | `hoard/downloader.py:1197` | **Jinxxy: when a button's label disappears after a re-render, the button now in the same position is downloaded.** It's saved under the old file's record, so the real file is never fetched. |
| D4 | `hoard/local.py:73` | **Adding a folder that contains the downloads folder isn't refused.** For example `~/Documents`: Hoard copies its own downloads, Local included, into Local. |
| D5 | `hoard/local.py:160` | **One file name the safety check refuses (`Preview?.png` on Mac or Linux) stops a Local copy part way.** The files copied so far are left on disk with no record. |
| D6 | `Packages/…/ImportLog.cs:33` | **An unreadable or locked `imports.json` (VCS, antivirus, merge marker) reads as empty.** The next import then rewrites it with one entry, wiping the project's import history. |
| D7 | `hoard/downloader.py:387` | **A manifest changed outside Hoard is copied to `_manifest.changed-<time>.json` every time it's opened read-only.** It's never re-sealed, so the copies pile up without limit. |
| D8 | `hoard/jobs.py:574` | **Stop during a move's catalog rebuild reports "Nothing was moved"** after the files have moved. The catalog and the folder's last-seen list are then out of date. |
| D9 | `hoard/asset_updates.py:90` | **An update is cleared once any of its files downloads.** Files left out (PR #119) or never reached because the run stopped are then no longer offered. |
| D10 | `hoard/jobs.py:853` | **A check for updates on one item (`item`/`only`) is recorded as a full check of the store.** Every other product's recorded updates are wiped. |
| D11 | `hoard/libraries.py:149` | **`remember()` reads and writes `library_folders.json` with no lock.** Concurrent catalog builds can lose a folder's last-seen list, and Hoard then re-downloads those products while that drive is away. |

## 3. Choosing files (PR #119)

| # | Where | Problem |
|---|---|---|
| F1 | `hoard/downloader.py:184` | **Choices are keyed by `tag_key`, which collides for products differing only by version or (label).** "Outfit (PC)" and "Outfit (Quest)" give the same key (**verified**). One product's choices then skip the other's files. |
| F2 | `hoard/web/*.html` | **Two files with the same name share one tickbox,** and both are left out. |

| F4 | `hoard/downloader.py:1180` | **Choices are matched on display text.** A Jinxxy row label that changes ("Updated 2 days ago"), or Booth names trimmed by `clean_text`, make a chosen file count as left out. |
| F5 | `hoard/downloader.py:1366` | **For a chosen Jinxxy item, the name comes from the item page, not the library.** Choices are ignored and its update entry never clears. |

## 7. Performance and duplication (not bugs)

Each of these makes the app slower than it needs to be, or means a fix has to be made in two places:

- `HoardWindow.cs:426`: `packages.Status` on every GUI event.
- `ThumbnailCache.cs:55`, `:85`: decodes aren't throttled, and textures can leak.
- `PackageIndex.cs:84`: an unwritable cache is retried on every editor tick.
- `server.py:627`: marks are read 3–4 times per request.
- `downloader.py:536`: marks are read for each product.
- `downloader.py:1667`: the folder is listed for each file.
- `egress.py:122`: a new Session for each request.
- `browser.py:469`: `_ended` grows forever.
- `server.py:1116`: `save_config` is repeated six times, only one copy is locked.
- About 1,000 lines of JavaScript are duplicated between the two pages and have drifted.
- Booth, Gumroad and Jinxxy parsers are duplicated in `downloader.py` and `library.py`.
- The deletion loop is duplicated.
- `ProjectReport` and `CreditsFile` share JSON and atomic-write code.
- `HoardWindow.StoreNames` copies `HoardCatalog`.
- `diagnostics.py:599` hard-codes the defaults.
