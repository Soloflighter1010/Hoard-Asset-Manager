## Hoard 열기

### "Hoard가 이 페이지를 알아보지 못했어요"

그 페이지에 이번 실행의 접근 키가 없어요. 오래된 북마크, Hoard를 다시 시작하기 전에 복사한 주소, 한 번만 쓸 수 있는 링크를 두 번 열었을 때 생겨요. 시작 메뉴에서 Hoard를 다시 열거나(창이 앞으로 나와요), 서버로 시작했다면 표시된 주소를 여세요. [다른 기기에서 쓰기](다른-기기에서-쓰기#접근-키)를 보세요.

### "Hoard가 이미 실행 중이지만 응답하지 않아요"

다른 Hoard가 열려 있지만 응답하지 않아요. 닫은 다음(작업 관리자에서 **Hoard**를 끝내기), 또는 컴퓨터를 다시 시작한 다음 Hoard를 다시 여세요.

### "이 PC에서 Hoard 창을 열 수 없어서"

Hoard 창에는 Microsoft Edge WebView2가 필요해요. 대신 웹 브라우저에서 열리고, 거기서 모든 것이 돼요. 종료하려면 **설정**에서 **Hoard 종료**를 고르세요. 창을 다시 쓰려면 Microsoft에서 WebView2 런타임을 설치한 다음 Hoard를 다시 여세요.

### "Hoard가 실행 중이 아니에요. 다시 여세요."

페이지가 Hoard의 서버를 잃었어요. Hoard가 종료됐거나 닫혔어요. Hoard를 다시 여세요.

### "Windows의 PC 보호"

Windows는 아직 잘 모르는 게시자의 앱에 대해 이렇게 표시해요. Hoard는 코드 서명이 되어 있어요. **추가 정보**를 고르면 게시자로 Hoard의 관리자가 보여요. 새 게시자는 릴리스를 설치하는 사람이 늘수록 Microsoft의 신뢰를 얻어서, 이 경고는 시간이 지나면 사라져요. **실행**을 고르세요. 먼저 파일을 확인하려면 [Hoard 설치](Hoard-설치#다운로드한-파일-확인하기)를 보세요.

### 스마트 앱 컨트롤, 메모리 무결성, TPM(Windows 11)

- **메모리 무결성**(Windows 보안의 코어 격리)은 켜 둬도 괜찮아요. 안전하지 않은 드라이버를 막는 기능인데, Hoard는 드라이버를 설치하지 않아요. Hoard의 프로그램, 브라우저, 창(Microsoft Edge WebView2)은 보통 앱이에요.
- **스마트 앱 컨트롤**도 켜 둬도 괜찮아요. Hoard의 프로그램과 설치 프로그램에는 코드 서명이 있고, Python 실행 환경, Playwright의 브라우저, Edge WebView2에는 각각 만든 곳의 서명이 있어요. Hoard에 들어 있는 작은 라이브러리 몇 개에는 서명이 없어요. 스마트 앱 컨트롤이 Hoard의 일부를 막으면 Windows가 막은 파일의 이름을 보여 줘요. 그 이름과 함께 [알려 주세요](#문제-알리기)(지원 보고서에는 스마트 앱 컨트롤과 메모리 무결성이 켜져 있는지가 들어가요). 스마트 앱 컨트롤은 Windows를 다시 설치하지 않으면 다시 켤 수 없으니, 끄기 전에 알려 주세요.
- **TPM은 필요 없어요.** 스토어 로그인과 API 키는 내 Windows 계정(DPAPI)으로 보호돼요. TPM이 있든 없든, BitLocker나 Windows Hello가 TPM을 쓰든 안 쓰든 똑같이 동작해요.

## 로그인

### Google, Discord, X로 로그인이 안 돼요

2.11부터 돼요. 로그인 창은 브라우저 자체의 창이라 Google 등이 받아들여요. 그래도 거부하면(또는 `config.json`에서 `"automated_sign_in": true`로 했다면), 평소 쓰는 브라우저에서 스토어 계정에 비밀번호를 설정한 다음, Hoard 창에서 그 비밀번호로 로그인하세요. 저장한 비밀번호를 찾는 방법은 [시작하기](시작하기#저장한-비밀번호-없이-로그인하기)를 보세요.

### "Booth에 로그인하지 않았어요", "세션이 만료됐어요"

스토어가 Hoard의 로그인을 끝냈어요. 스토어는 가끔 그렇게 해요. **스토어**에서 그 스토어의 **로그인**을 다시 고르세요.

### "다른 Hoard 도구가 지금 … 로그인을 쓰고 있어요"

스토어 로그인은 한 번에 한 프로그램만 쓸 수 있어요. 다른 Hoard나 `hoard-cli` 명령이 쓰고 있어요. 끝날 때까지 기다리거나 닫으세요.

### 로그인이 저장되지 않아요(Linux)

Hoard는 보호할 수 있는 로그인만 보관하고, 그러려면 키링이 필요해요. GNOME Keyring, Secret Service를 켠 KeePassXC, 또는 KWallet이에요. 하나를 설치하고 잠금을 푼 다음 다시 로그인하세요. [스토어](스토어#로그인)를 보세요.

### "Hoard의 브라우저가 아직 설치되지 않았어요"

스토어에 로그인할 때 필요하면 먼저 Hoard의 브라우저를 다운로드해요(약 150 MB, 한 번만). 다른 일에 그게 필요하다면 **설정**을 열고, **Hoard 다시 설정**을 고른 다음, **Hoard 브라우저 설치**를 고르세요. 메시지에 **설정**에서 고른 브라우저 이름이 나오면, 거기서 대신 다른 브라우저를 고르세요. Linux에서 그래도 브라우저가 시작되지 않으면 Hoard 폴더에서 `.venv/bin/python -m playwright install-deps chromium`을 실행하세요(소스에서 실행할 때).

## 스토어

### 스토어가 제대로 읽히지 않아요

스토어는 웹사이트를 바꾸고, Hoard가 업데이트될 때까지 읽기가 안 될 수 있어요.

1. [최신 버전](https://github.com/Soloflighter1010/Hoard-Asset-Manager/releases/latest)인지 확인하세요.
2. 그동안 보통은 직접 저장한 페이지를 가져올 수 있어요. [스토어](스토어#저장한-페이지-가져오기)를 보세요.
3. `hoard-cli debug <store>`(또는 `hoard-cli probe jinxxy`)를 실행하세요. 라이브러리 페이지와 Hoard가 읽은 것의 요약을 개인 정보를 지워서 Hoard 앱 데이터 폴더의 `debug` 폴더에 저장해요.
4. [이슈를 열고](https://github.com/Soloflighter1010/Hoard-Asset-Manager/issues) 그걸 첨부하세요. 단, **먼저 읽어 본 다음에** 하세요. 산 것이 여전히 보이고, GitHub 이슈는 공개돼요.

### Payhip이 봇 확인을 계속 보여 줘요

Payhip이 열린 창에서 확인을 마치면 Hoard가 이어서 해요(최대 3분 기다려요). 그래도 Payhip이 Hoard를 들여보내지 않으면, 대신 평소 쓰는 브라우저에서 상점마다 라이브러리 페이지를 저장해서 한꺼번에 가져오세요. [스토어](스토어#payhip)를 보세요.

### Payhip에 아무것도 없거나, 산 것의 일부만 보여요

Payhip은 구매품을 상점마다 15개씩 페이지로 보관해서, Hoard는 추가한 상점이나 가져온 페이지만 볼 수 있어요. 모든 상점 라이브러리의 모든 페이지를 가져오거나(**폴더 가져오기**로 한 번에 가져와요), **설정**의 **Payhip 상점**에 상점을 추가하고 새로고침하세요.

### "Hoard doesn't download from Payhip"(Hoard는 Payhip에서 다운로드하지 않아요)

맞아요. Hoard는 Payhip에서 산 것을 목록으로 보여 주고, 파일은 Payhip에서 다운로드해요. 라이브러리에서 상품을 열고 **Payhip에서 열기**를 고르세요. [스토어](스토어#payhip)를 보세요.

### 가져오지 못한 페이지가 있어요

가져오기가 끝나면 Hoard는 쓰지 못한 페이지와 그 이유를 보여 줘요.

- **"어느 스토어의 페이지인지 알 수 없었어요":** 스토어 라이브러리에서 저장한 페이지가 아니거나, 텍스트만 저장됐어요. 라이브러리 페이지 자체를 **웹페이지, 단일 파일**로 저장하거나, **스토어**에서 그 스토어 줄로 가져오세요(**페이지 가져오기**). 그러면 Hoard에 스토어를 알려 줘요.
- **"그 페이지에 … 상품이 없어요":** 다 불러오기 전에 페이지를 저장했어요. 먼저 맨 아래까지 스크롤한 다음 다시 저장하세요.
- **추가하지 않은 Payhip 상점:** Hoard는 확인했을 때만 상점을 추가해요. 페이지를 다시 가져오고 Hoard가 물으면 **확인**을 고르거나, **설정**에서 상점을 추가하세요.

### itch.io: "itch.io가 API 키를 받아들이지 않았어요"

키를 잘못 입력했거나, 복사할 때 잘렸거나, itch.io에서 지웠어요. itch.io에서 새 키를 만들고(Settings, API keys), **스토어**의 itch.io 줄에서 **API 키 변경**을 고르세요. [스토어](스토어#itchio)를 보세요.

### itch.io가 내 파일 일부를 건너뛰어요

제작자가 Windows, macOS, Linux, Android용 프로그램으로 표시한 파일은 게임 빌드라서, **설정**의 itch.io에서 **게임 빌드(Windows, macOS, Linux, Android용 파일) 건너뛰기**를 끄지 않으면 건너뛰어요. 다른 웹사이트에 둔 파일(요약에 그렇게 나와요)은 내가 거기서 다운로드해요. 번들의 프로젝트는 itch.io에서 받아야 수에 들어가요.

### "Booth turned the direct download away"(Booth가 직접 다운로드를 거절했어요)

할 일은 없어요. Hoard가 알아서 그 파일을 브라우저로 다운로드해요(Booth가 또 거절하면 그 실행의 나머지도).

### "Couldn't reach booth.pm, so Booth wasn't refreshed"(booth.pm에 연결할 수 없어서 Booth를 새로고침하지 않았어요)

오프라인이거나 스토어가 멈췄어요. 저장된 라이브러리와 다운로드는 그대로예요. 나중에 다시 해 보세요.

## 다운로드

### "The download stopped at ... bytes; the next sync resumes it"(다운로드가 … 바이트에서 멈췄어요. 다음 동기화에서 이어서 해요)

파일을 다 받기 전에 연결이 끊겼어요. 잃은 건 없어요. 다음 동기화가 멈춘 곳부터 이어서 해요.

### 다운로드가 계속 실패하거나 건너뛰어져요

다운로드가 끝날 때마다 나오는 요약에 실패하거나 건너뛴 모든 것의 이유가 있어요. Gumroad의 "no download page"(다운로드 페이지 없음)는 환불이나 끝난 멤버십이라는 뜻이고, Gumroad가 스트리밍으로만 보여 주는 파일은 다운로드할 수 없어요. 라이브러리에서 삭제한 상품은 일부러 건너뛰어요.

### 기록이 "was changed by something other than Hoard"(Hoard가 아닌 다른 것에 의해 바뀌었어요)

무언가가 Hoard의 기록을 편집했어요. Hoard는 바뀐 파일의 사본을 남기고, 그 링크를 더 이상 믿지 않고, 다음 동기화 때 스토어에서 다시 가져와요. `hoard-cli verify`로 모두 점검하세요. 다운로드 폴더를 여러 컴퓨터에서 같이 쓴다면 `integrity.key`를 복사하세요. [Hoard가 저장하는 곳](Hoard가-저장하는-곳#다운로드-폴더-하나를-컴퓨터-두-대에서)을 보세요.

### "Hoard's saved list was saved by Hoard on another computer"(저장된 목록은 다른 컴퓨터의 Hoard가 저장한 것이에요)

라이브러리 목록이 다른 컴퓨터의 Hoard에서 왔어요(앱 데이터 폴더를 복사했다거나). 그 링크와 이미지는 스토어를 새로고침할 때까지 숨겨져요. 그대로 쓰려면 그 컴퓨터의 `integrity.key`도 복사하세요.

### 파일이 "is damaged"(손상됨)이고 "kept as ...damaged-..."로 남았어요

Hoard가 그 파일을 읽지 못해서, 덮어쓰지 않고 따로 두고 계속했어요. 새로고침이나 동기화가 그 내용을 다시 만들어요.

## 숨긴 라이브러리

- **PIN을 잊었나요?** **PIN을 잊었나요?** 버튼을 고르고 복구 단어 6개를 입력해서 새 PIN을 정하세요. 잃는 건 없어요.
- **단어도 잃어버렸나요?** 빠져나가는 방법은 하나뿐이에요. 숨긴 아이템을 보여 주지 않고 Hoard의 목록에서 지워요.
- **"너무 많이 틀렸어요. …초 뒤에 다시 해 보세요."** 다섯 번 틀리면 그다음부터는 시도할 때마다 더 오래 기다려야 해요(30초부터 두 배씩, 최대 한 시간). Hoard를 다시 시작해도 마찬가지예요.

[라이브러리](라이브러리#숨긴-라이브러리)를 보세요.

## 문제 알리기

가장 쉬운 방법은 Hoard가 기술적인 자세한 내용을 준비하게 하는 거예요.

1. 할 수 있다면 문제를 다시 일으켜 보세요.
2. **설정**에서 **지원 보고서 만들기**를 고르거나, 실패한 스토어나 다운로드 옆에 나오는 **보고서 만들기** 버튼을 쓰세요.
3. 보고서 미리보기를 읽은 다음 저장하세요. Hoard는 내 컴퓨터에서 ZIP을 만들고, 내보내기 전에 개인 정보를 지워요. 자동으로 업로드되지 않아요.
4. [이슈를 열고](https://github.com/Soloflighter1010/Hoard-Asset-Manager/issues) ZIP을 첨부하세요. 공개 이슈이니 공유하기 전에 직접 ZIP 내용을 확인하세요.

관리자가 더 깊은 문제 해결을 부탁하면 예전부터 있던 `hoard-cli debug <store>`와 `hoard-cli probe jinxxy` 명령도 쓸 수 있어요.

보안 문제를 찾았다면 대신 비공개로 알려 주세요. [보안과 개인정보](보안과-개인정보#보안-문제-알리기)를 보세요.
